   118→## Motivation
   119→
   120→`pdf-lib` was created to address the JavaScript ecosystem's lack of robust support for PDF manipulation (especially for PDF _modification_).
   121→
   122→Two of `pdf-lib`'s distinguishing features are:
   123→
   124→1. Supporting modification (editing) of existing documents.
   125→2. Working in all JavaScript environments - not just in Node or the Browser.
   126→
   127→There are [other](#prior-art) good open source JavaScript PDF libraries available. However, most of them can only _create_ documents, they cannot _modify_ existing ones. And many of them only work in particular environments.

   138→```js
   139→import { PDFDocument, StandardFonts, rgb } from 'pdf-lib-plus-encrypt'
   140→
   141→// Create a new PDFDocument
   142→const pdfDoc = await PDFDocument.create()
   143→
   144→// Embed the Times Roman font
   145→const timesRomanFont = await pdfDoc.embedFont(StandardFonts.TimesRoman)
   146→
   147→// Add a blank page to the document
   148→const page = pdfDoc.addPage()
   149→
   150→// Get the width and height of the page
   151→const { width, height } = page.getSize()
   152→
   153→// Draw a string of text toward the top of the page
   154→const fontSize = 30
   155→page.drawText('Creating PDFs in JavaScript is awesome!', {
   156→  x: 50,
   157→  y: height - 4 * fontSize,
   158→  size: fontSize,
   159→  font: timesRomanFont,
   160→  color: rgb(0, 0.53, 0.71),
   161→})
   162→
   163→// Serialize the PDFDocument to bytes (a Uint8Array)
   164→const pdfBytes = await pdfDoc.save()
   165→
   166→// For example, `pdfBytes` can be:
   167→//   • Written to a file in Node
   168→//   • Downloaded from the browser
   169→//   • Rendered in an <iframe>
   170→```

   478→### Copy Pages
   479→
   480→_This example produces [this PDF](assets/pdfs/examples/copy_pages.pdf)_ (when [this PDF](assets/pdfs/with_update_sections.pdf) is used for the `firstDonorPdfBytes` variable and [this PDF](assets/pdfs/with_large_page_count.pdf) is used for the `secondDonorPdfBytes` variable).
   481→
   482→[Try the JSFiddle demo](https://jsfiddle.net/Hopding/ybank8s9/2/)
   483→
   484→<!-- prettier-ignore -->
   485→```js
   486→import { PDFDocument } from 'pdf-lib-plus-encrypt'
   487→
   488→// Create a new PDFDocument
   489→const pdfDoc = await PDFDocument.create()
   490→
   491→// These should be Uint8Arrays or ArrayBuffers
   492→// This data can be obtained in a number of different ways
   493→// If your running in a Node environment, you could use fs.readFile()
   494→// In the browser, you could make a fetch() call and use res.arrayBuffer()
   495→const firstDonorPdfBytes = ...
   496→const secondDonorPdfBytes = ...
   497→
   498→// Load a PDFDocument from each of the existing PDFs
   499→const firstDonorPdfDoc = await PDFDocument.load(firstDonorPdfBytes)
   500→const secondDonorPdfDoc = await PDFDocument.load(secondDonorPdfBytes)
   501→
   502→// Copy the 1st page from the first donor document, and 
   503→// the 743rd page from the second donor document
   504→const [firstDonorPage] = await pdfDoc.copyPages(firstDonorPdfDoc, [0])
   505→const [secondDonorPage] = await pdfDoc.copyPages(secondDonorPdfDoc, [742])
   506→
   507→// Add the first copied page
   508→pdfDoc.addPage(firstDonorPage)
   509→
   510→// Insert the second copied page to index 0, so it will be the 
   511→// first page in `pdfDoc`
   512→pdfDoc.insertPage(0, secondDonorPage)
   513→
   514→// Serialize the PDFDocument to bytes (a Uint8Array)
   515→const pdfBytes = await pdfDoc.save()
   516→
   517→// For example, `pdfBytes` can be:
   518→//   • Written to a file in Node
   519→//   • Downloaded from the browser
   520→//   • Rendered in an <iframe>
   521→```

   529→<!-- prettier-ignore -->
   530→```js
   531→import { PDFDocument } from 'pdf-lib-plus-encrypt'
   532→
   533→// These should be Uint8Arrays or ArrayBuffers
   534→// This data can be obtained in a number of different ways
   535→// If your running in a Node environment, you could use fs.readFile()
   536→// In the browser, you could make a fetch() call and use res.arrayBuffer()
   537→const jpgImageBytes = ...
   538→const pngImageBytes = ...
   539→
   540→// Create a new PDFDocument
   541→const pdfDoc = await PDFDocument.create()
   542→
   543→// Embed the JPG image bytes and PNG image bytes
   544→const jpgImage = await pdfDoc.embedJpg(jpgImageBytes)
   545→const pngImage = await pdfDoc.embedPng(pngImageBytes)
   546→
   547→// Get the width/height of the JPG image scaled down to 25% of its original size
   548→const jpgDims = jpgImage.scale(0.25)
   549→
   550→// Get the width/height of the PNG image scaled down to 50% of its original size
   551→const pngDims = pngImage.scale(0.5)

   877→const viewerPrefs = pdfDoc.catalog.getOrCreateViewerPreferences()

   880→viewerPrefs.setHideWindowUI(true)

  1013→## Deno Usage
  1014→
  1015→`pdf-lib` fully supports the exciting new [Deno](https://deno.land/) runtime! All of the [usage examples](#usage-examples) work in Deno. The only thing you need to do is change the imports for `pdf-lib` and `@pdf-lib/fontkit` to use the [Skypack](https://www.skypack.dev/) CDN, because Deno requires all modules to be referenced via URLs.
  1016→
  1017→> **See also [How to Create and Modify PDF Files in Deno With pdf-lib](https://medium.com/swlh/how-to-create-and-modify-pdf-files-in-deno-ffaad7099b0?source=friends_link&sk=3da183bb776d059df428eaea52102f19)**
  1018→
  1019→### Creating a Document with Deno
  1020→
  1021→Below is the [**create document**](#create-document) example modified for Deno:
  1022→
  1023→```js
  1024→import {
  1025→  PDFDocument,
  1026→  StandardFonts,
  1027→  rgb,
  1028→} from 'https://cdn.skypack.dev/pdf-lib@^1.11.1?dts';
  1029→
  1030→const pdfDoc = await PDFDocument.create();
  1031→const timesRomanFont = await pdfDoc.embedFont(StandardFonts.TimesRoman);
  1032→
  1033→const page = pdfDoc.addPage();
  1034→const { width, height } = page.getSize();
  1035→const fontSize = 30;
  1036→page.drawText('Creating PDFs in JavaScript is awesome!', {
  1037→  x: 50,
  1038→  y: height - 4 * fontSize,
  1039→  size: fontSize,
  1040→  font: timesRomanFont,
  1041→  color: rgb(0, 0.53, 0.71),
  1042→});
  1043→
  1044→const pdfBytes = await pdfDoc.save();
  1045→
  1046→await Deno.writeFile('out.pdf', pdfBytes);
  1047→```
  1048→
  1049→If you save this script as `create-document.ts`, you can execute it using Deno with the following command:
  1050→
  1051→```
  1052→deno run --allow-write create-document.ts
  1053→```
  1054→
  1055→The resulting `out.pdf` file will look like [this PDF](assets/pdfs/examples/create_document.pdf).

  1095→  width: textWidth,
  1096→  height: textHeight,
  1097→  borderColor: rgb(1, 0, 0),
  1098→  borderWidth: 1.5,
  1099→});
  1100→
  1101→const pdfBytes = await pdfDoc.save();
  1102→
  1103→await Deno.writeFile('out.pdf', pdfBytes);
  1104→```
  1105→
  1106→If you save this script as `custom-font.ts`, you can execute it with the following command:
  1107→
  1108→```
  1109→deno run --allow-write --allow-net custom-font.ts
  1110→```
  1111→
  1112→The resulting `out.pdf` file will look like [this PDF](assets/pdfs/examples/embed_font_and_measure_text.pdf).

  1224→## Fonts and Unicode
  1225→
  1226→When working with PDFs, you will frequently come across the terms "character encoding" and "font". If you have experience in web development, you may wonder why these are so prevalent. Aren't they just annoying details that you shouldn't need to worry about? Shouldn't PDF libraries and readers be able to handle all of this for you like web browsers can? Unfortunately, this is not the case. The nature of the PDF file format makes it very difficult to avoid thinking about character encodings and fonts when working with PDFs.
  1227→
  1228→`pdf-lib` does its best to simplify things for you. But it can't perform magic. This means you should be aware of the following:
  1229→
  1230→- **There are 14 standard fonts** defined in the PDF specification. They are as follows: _Times Roman_ (normal, bold, and italic), _Helvetica_ (normal, bold, and italic), _Courier_ (normal, bold, and italic), _ZapfDingbats_ (normal), and _Symbol_ (normal). These 14 fonts are guaranteed to be available in PDF readers. As such, you do not need to embed any font data if you wish to use one of these fonts. You can use a standard font like so:
  1231→  <!-- prettier-ignore -->
  1232→  ```js
  1233→  import { PDFDocument, StandardFonts } from 'pdf-lib-plus-encrypt'
  1234→  const pdfDoc = await PDFDocument.create()
  1235→  const courierFont = await pdfDoc.embedFont(StandardFonts.Courier)
  1236→  const page = pdfDoc.addPage()
  1237→  page.drawText('Some boring latin text in the Courier font', { 
  1238→    font: courierFont,
  1239→  })
  1240→  ```
  1241→- **The standard fonts do not support all characters** available in Unicode. The Times Roman, Helvetica, and Courier fonts use WinAnsi encoding (aka [Windows-1252](https://en.wikipedia.org/wiki/Windows-1252)). The WinAnsi character set only supports 218 characters in the Latin alphabet. For this reason, many users will find the standard fonts insufficient for their use case. This is unfortunate, but there's nothing that PDF libraries can do to change this. This is a result of the PDF specification and its age. Note that the [ZapfDingbats](https://en.wikipedia.org/wiki/Zapf_Dingbats) and [Symbol](<https://en.wikipedia.org/wiki/Symbol_(typeface)>) fonts use their own specialized encodings that support 203 and 194 characters, respectively. However, the characters they support are not useful for most use cases. See [here](assets/pdfs/standard_fonts_demo.pdf) for an example of all 14 standard fonts.
  1242→- **You can use characters outside the Latin alphabet** by embedding your own fonts. Embedding your own font requires to you load the font data (from a file or via a network request, for example) and pass it to the `embedFont` method. When you embed your own font, you can use any Unicode characters that it supports. This capability frees you from the limitations imposed by the standard fonts. Most PDF files use embedded fonts. You can embed and use a custom font like so ([see also](#embed-font-and-measure-text)):
  1243→  <!-- prettier-ignore -->
  1244→  ```js
  1245→  import { PDFDocument } from 'pdf-lib-plus-encrypt'
  1246→  import fontkit from '@pdf-lib/fontkit'
  1247→
  1248→  const url = 'https://pdf-lib.js.org/assets/ubuntu/Ubuntu-R.ttf'
  1249→  const fontBytes = await fetch(url).then((res) => res.arrayBuffer())
  1250→
  1251→  const pdfDoc = await PDFDocument.create()
  1252→
  1253→  pdfDoc.registerFontkit(fontkit)
  1254→  const ubuntuFont = await pdfDoc.embedFont(fontBytes)
  1255→
  1256→  const page = pdfDoc.addPage()
  1257→  page.drawText('Some fancy Unicode text in the ŪЬȕǹƚü font', { 
  1258→    font: ubuntuFont,
  1259→  })
  1260→  ```
  1261→
  1262→Note that encoding errors will be thrown if you try to use a character with a font that does not support it. For example, `Ω` is not in the WinAnsi character set. So trying to draw it on a page with the standard Helvetica font will throw the following error:
  1263→
  1264→```
  1265→Error: WinAnsi cannot encode "Ω" (0x03a9)
  1266→    at Encoding.encodeUnicodeCodePoint
  1267→```
  1268→
  1269→### Font Subsetting
  1270→
  1271→Embedding a font in a PDF document will typically increase the file's size. You can reduce the amount a file's size is increased by subsetting the font so that only the necessary characters are embedded. You can subset a font by setting the [`subset` option](https://pdf-lib.js.org/docs/api/interfaces/embedfontoptions#optional-subset) to `true`. For example:
  1272→
  1273→```js
  1274→const font = await pdfDoc.embedFont(fontBytes, { subset: true });
  1275→```
  1276→
  1277→Note that subsetting does not work for all fonts. See https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/207#issuecomment-537210471 for additional details.

  1281→`pdf-lib` can create, fill, and read PDF form fields. The following field types are supported:

  1286→- [Option Lists](https://pdf-lib.js.org/docs/api/classes/pdfoptionlist)
  1287→- [Radio Groups](https://pdf-lib.js.org/docs/api/classes/pdfradiogroup)
  1288→- [Text Fields](https://pdf-lib.js.org/docs/api/classes/pdftextfield)
  1289→
  1290→See the [form creation](#create-form) and [form filling](#fill-form) usage examples for code samples. Tests 1, 14, 15, 16, and 17 in the [complete examples](#complete-examples) contain working example code for form creation and filling in a variety of different JS environments.
  1291→
  1292→**IMPORTANT:** The default font used to display text in buttons, dropdowns, option lists, and text fields is the standard Helvetica font. This font only supports characters in the latin alphabet (see [Fonts and Unicode](#fonts-and-unicode) for details). This means that if any of these field types are created or modified to contain text outside the latin alphabet (as is often the case), you will need to embed and use a custom font to update the field appearances. Otherwise an error will be thrown (likely when you save the `PDFDocument`).
  1293→
  1294→You can use an embedded font when filling form fields as follows:
  1295→
  1296→```js
  1297→import { PDFDocument } from 'pdf-lib-plus-encrypt';
  1298→import fontkit from '@pdf-lib/fontkit';
  1299→
  1300→// Fetch the PDF with form fields
  1301→const formUrl = 'https://pdf-lib.js.org/assets/dod_character.pdf';
  1302→const formBytes = await fetch(formUrl).then((res) => res.arrayBuffer());
  1303→
  1304→// Fetch the Ubuntu font
  1305→const fontUrl = 'https://pdf-lib.js.org/assets/ubuntu/Ubuntu-R.ttf';
  1306→const fontBytes = await fetch(fontUrl).then((res) => res.arrayBuffer());
  1307→
  1308→// Load the PDF with form fields
  1309→const pdfDoc = await PDFDocument.load(formBytes);
  1310→
  1311→// Embed the Ubuntu font
  1312→pdfDoc.registerFontkit(fontkit);
  1313→const ubuntuFont = await pdfDoc.embedFont(fontBytes);
  1314→
  1315→// Get two text fields from the form
  1316→const form = pdfDoc.getForm();
  1317→const nameField = form.getTextField('CharacterName 2');
  1318→const ageField = form.getTextField('Age');
  1319→
  1320→// Fill the text fields with some fancy Unicode characters (outside
  1321→// the WinAnsi latin character set)
  1322→nameField.setText('Ӎӑȑїõ');
  1323→ageField.setText('24 ŷȇȁŗš');
  1324→
  1325→// **Key Step:** Update the field appearances with the Ubuntu font
  1326→form.updateFieldAppearances(ubuntuFont);
  1327→
  1328→// Save the PDF with filled form fields
  1329→const pdfBytes = await pdfDoc.save();
  1330→```

  1390→## Limitations
  1391→
  1392→- `pdf-lib` **can** extract the content of text fields (see [`PDFTextField.getText`](https://pdf-lib.js.org/docs/api/classes/pdftextfield#gettext)), but it **cannot** extract plain text on a page outside of a form field. This is a difficult feature to implement, but it is within the scope of this library and may be added to `pdf-lib` in the future. See
  1393→  [#93](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/93),
  1394→  [#137](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/137),
  1395→  [#177](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/177),
  1396→  [#329](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/329), and
  1397→  [#380](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/380).
  1398→- `pdf-lib` **can** remove and edit the content of text fields (see [`PDFTextField.setText`](https://pdf-lib.js.org/docs/api/classes/pdftextfield#settext)), but it does **not** provide APIs for removing or editing text on a page outside of a form field. This is also a difficult feature to implement, but is within the scope of `pdf-lib` and may be added in the future. See
  1399→  [#93](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/93),
  1400→  [#137](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/137),
  1401→  [#177](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/177),
  1402→  [#329](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/329), and
  1403→  [#380](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/380).
  1404→- `pdf-lib` does **not** support the use of HTML or CSS when adding content to a PDF. Similarly, `pdf-lib` **cannot** embed HTML/CSS content into PDFs. As convenient as such a feature might be, it would be extremely difficult to implement and is far beyond the scope of this library. If this capability is something you need, consider using [Puppeteer](https://github.com/puppeteer/puppeteer).

  1412→## Encryption Handling
  1413→
  1414→**`pdf-lib` does not currently support encrypted documents.** You should not use `pdf-lib` with encrypted documents. However, this is a feature that could be added to `pdf-lib`. Please [create an issue](https://github.com/brennanmcquerry/pdf-lib-plus-encrypt/issues/new) if you would find this feature helpful!
  1415→
  1416→When an encrypted document is passed to `PDFDocument.load(...)`, an error will be thrown:
  1417→
  1418→<!-- prettier-ignore -->
  1419→```js
  1420→import { PDFDocument, EncryptedPDFError } from 'pdf-lib-plus-encrypt'
  1421→
  1422→const encryptedPdfBytes = ...
  1423→
  1424→// Assignment fails. Throws an `EncryptedPDFError`.
  1425→const pdfDoc = PDFDocument.load(encryptedPdfBytes)
  1426→```
  1427→
  1428→This default behavior is usually what you want. It allows you to easily detect if a given document is encrypted, and it prevents you from trying to modify it. However, if you really want to load the document, you can use the `{ ignoreEncryption: true }` option:
  1429→
  1430→```js
  1431→import { PDFDocument } from 'pdf-lib-plus-encrypt'
  1432→
  1433→const encryptedPdfBytes = ...
  1434→
  1435→// Assignment succeeds. Does not throw an error.
  1436→const pdfDoc = PDFDocument.load(encryptedPdfBytes, { ignoreEncryption: true })
  1437→```
  1438→
  1439→Note that **using this option does not decrypt the document**. This means that any modifications you attempt to make on the returned `PDFDocument` may fail, or have unexpected results.
  1440→
  1441→**You should not use this option.** It only exists for backwards compatibility reasons.

  1462→## Prior Art
  1463→
  1464→- [`pdfkit`](https://github.com/devongovett/pdfkit) is a PDF generation library for Node and the Browser. This library was immensely helpful as a reference and existence proof when creating `pdf-lib`. `pdfkit`'s code for [font embedding](src/core/embedders/CustomFontEmbedder.ts#L17-L21), [PNG embedding](src/core/embedders/PngEmbedder.ts#L7-L11), and [JPG embedding](src/core/embedders/JpegEmbedder.ts#L25-L29) was especially useful.
  1465→- [`pdf.js`](https://github.com/mozilla/pdf.js) is a PDF rendering library for the Browser. This library was helpful as a reference when writing `pdf-lib`'s parser. Some of the code for stream decoding was [ported directly to TypeScript](src/core/streams) for use in `pdf-lib`.
  1466→- [`pdfbox`](https://pdfbox.apache.org/) is a PDF generation and modification library written in Java. This library was an invaluable reference when implementing form creation and filling APIs for `pdf-lib`.
  1467→- [`jspdf`](https://github.com/MrRio/jsPDF) is a PDF generation library for the browser.
  1468→- [`pdfmake`](https://github.com/bpampuch/pdfmake) is a PDF generation library for the browser.
  1469→- [`hummus`](https://github.com/galkahana/HummusJS) is a PDF generation and modification library for Node environments. `hummus` is a Node wrapper around a [C++ library](https://github.com/galkahana/PDF-Writer), so it doesn't work in many JavaScript environments - like the Browser or React Native.
  1470→- [`react-native-pdf-lib`](https://github.com/Hopding/react-native-pdf-lib) is a PDF generation and modification library for React Native environments. `react-native-pdf-lib` is a wrapper around [C++](https://github.com/galkahana/PDF-Writer) and [Java](https://github.com/TomRoush/PdfBox-Android) libraries.
  1471→- [`pdfassembler`](https://github.com/DevelopingMagic/pdfassembler) is a PDF generation and modification library for Node and the browser. It requires some knowledge about the logical structure of PDF documents to use.

  1473→## Git History Rewrite
  1474→
  1475→This repo used to contain a file called `pdf_specification.pdf` in the root directory. This was a copy of the [PDF 1.7 specification](https://www.adobe.com/content/dam/acom/en/devnet/pdf/pdfs/PDF32000_2008.pdf), which is made freely available by Adobe. On 8/30/2021, we received a DMCA complaint requiring us to remove the file from this repo. Simply removing the file via a new commit to `master` was insufficient to satisfy the complaint. The file needed to be completely removed from the repo's git history. Unfortunately, the file was added over two years ago, this meant we had to rewrite the repo's git history and force push to `master` 😔.
  1476→
  1477→### Steps We Took
  1478→
  1479→We removed the file and rewrote the repo's history using [BFG Repo-Cleaner](https://rtyley.github.io/bfg-repo-cleaner/) as outlined [here](https://docs.github.com/en/github/authenticating-to-github/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository). For full transparency, here are the exact commands we ran:
  1480→
  1481→```
  1482→$ git clone git@github.com:brennanmcquerry/pdf-lib-plus-encrypt.git
  1483→$ cd pdf-lib
  1484→$ rm pdf_specification.pdf
  1485→$ git commit -am 'Remove pdf_specification.pdf'
  1486→$ bfg --delete-files pdf_specification.pdf
  1487→$ git reflog expire --expire=now --all && git gc --prune=now --aggressive
  1488→$ git push --force
  1489→```
  1490→
  1491→### Why Should I Care?
  1492→
  1493→If you're a user of `pdf-lib`, you shouldn't care! Just keep on using `pdf-lib` like normal 😃 ✨!
  1494→
  1495→If you are a `pdf-lib` developer (meaning you've forked `pdf-lib` and/or have an open PR) then this does impact you. If you forked or cloned the repo prior to 8/30/2021 then your fork's git history is out of sync with this repo's `master` branch. Unfortunately, this will likely be a headache for you to deal with. Sorry! We didn't want to rewrite the history, but there really was no alternative.
  1496→
  1497→It's important to note that pdf-lib's _source code_ has not changed at all. It's exactly the same as it was before the git history rewrite. The repo still has the exact same number of commits (and even the same commit contents, except for the commit that added `pdf_specification.pdf`). What has changed are the SHAs of those commits.
  1498→
  1499→The simplest way to deal with this fact is to:
  1500→
  1501→1. Reclone pdf-lib
  1502→2. Manually copy any changes you've made from your old clone to the new one
  1503→3. Use your new clone going forward
  1504→4. Reopen your unmerged PRs using your new clone
  1505→
  1506→See this [StackOverflow answer](https://stackoverflow.com/a/48268766) for a great, in depth explanation of what a git history rewrite entails.
